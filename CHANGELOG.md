# Changelog

All notable changes to `@arnilo/liveframe` are recorded here. The project follows the compatibility policy in [`docs/compatibility.md`](docs/compatibility.md).

## Unreleased

Fixed:

- **`compileValidator` keeps catalog work for 64 catalog and capabilities pairs (LF-34).** The cache held eight pairs and scanned them on every call; it now holds the 64 most recently used and finds a pair with one keyed lookup, so a host serving many catalogs no longer recompiles them in turn. A hit still requires the same document content, and a document changed after compiling still compiles again ([formats](docs/formats.md#validation)).

- **Directory drafts and capture errors stay inside the authoring boundary (LF-27, items 5–6).** MCP `pack_draft({ dir })` opens each draft file once, checks the open handle, and reads from it: a hard link inside `draftRoot` to a file outside it, or a file swapped for a symlink after its containment check, is `invalid-document` at `/dir`. The Playwright capture backend's missing-browser, unreachable-page and never-ready errors are fixed messages with no Playwright text, host path or URL.

- **Core validation and host hardening (LF-27, items 1–4).** Lone surrogates in source data produce a failed source outcome where supported and a pointed render error otherwise. String schemas skip `pattern` after a length failure. Element and template sections reject prototype-related names. A rejected intent leaves any recorded status for the offered action key intact and skips the render.

- **Inline authoring drafts are bounded before transpilation (LF-26).** MCP `pack_draft` and `authoring.packDraft()` refuse oversized inline source sets and JSON documents with `limit-exceeded` at the relevant input pointer.

- **A2UI conversion bounds data updates and formatted text (LF-25).** Sparse array writes, over-budget writes, deep data pointers and oversized formatted text return typed limit errors. Unexpected conversion failures return fixed diagnostics.

- **Widget exceptions keep render inputs out of default diagnostics (LF-21).** Widget throws use a fixed message with an allowlisted error name. Preview, authoring and package scenario checks request up to 1,000 characters of untrusted exception text in `LiveframeError.debug`. Production hosts can opt in with `runOptions.debug`; it also enables the field in their render failure events.

- **Template expansion stops at its budgets (LF-18).** Each emitted element or fragment and each entered `$use` spends a step. Expansion stops at the first element or fragment beyond the node limit and reports its template pointer.

- **Sized template operators spend steps in proportion to their work (LF-18).** The evaluator charges for string units and collection entries read or written. String `$slice` stops scanning at its end index. Fifty-eight full slices of a 1 MiB string exceed the default step budget.

- **Install validation rejects oversized unconditional template expansions (LF-18).** A template whose minimum expansion exceeds the install node limit returns `limit-exceeded` at the element, fragment or component use that crosses the limit.

Added:

- **Template budget conformance cases (LF-18).** The corpus covers static fan-out, the component depth boundary, and a template that installs successfully but exhausts the render step budget during a string slice. See the [corpus guide](docs/conformance.md#language-neutral-corpus).

## 0.4.0 — 2026-11-22

0.4.0 includes the fixes originally prepared for the unpublished 0.3.1 patch. The release adds interaction, rendering and agent authoring capabilities, including the first release of `@arnilo/liveframe-a2ui`. See the [migration guide](docs/migration-0.4.md), [adopter notes](docs/adopters-0.4.md) and [compatibility policy](docs/compatibility.md#040).

Added:

- **A new package converts A2UI to element JSON (`@arnilo/liveframe-a2ui`):** `fromA2ui(messages, mapping, options?)` reads one A2UI v0.9 or v0.9.1 surface (JSONL text or parsed messages: one `createSurface`, `updateComponents` merged by `id`, `updateDataModel` applied in order) and returns `Result<{ elements, initialLocal, origins }>`. The mapping is the app's: A2UI components to catalog kinds (`props`, `variants`, `children`, `lift`, `items`, `event`, `input`), event names to manifest actions, data paths to `local` keys, and the constructs it knowingly drops (`theme`, `weight`, `checks`). A2UI ids become element keys; templates expand to `<componentId>-<index>`; data paths and `formatString` over data paths resolve at conversion; an input bound to a mapped path becomes `bind` plus `setLocal`, and a context path becomes `fromLocal`. Client functions, `functionCall` actions, `svgPath`, `sendDataModel`, `deleteSurface`, a second surface, shared, cyclic or unreachable components, and anything the mapping does not name are typed errors with pointers into the A2UI input. Input is bounded as `streamElements` bounds its text. The converter does not validate: `renderElements` checks its output against the app's validator, and `origins` maps that error's pointer back to A2UI. It releases in lockstep and peers only on the core ([README](packages/a2ui/README.md)). Spec §14 no longer excludes A2UI interop.
- **Element JSON can ask for a live filter (`when`, `bind`, `setLocal`):** `renderElements` and `streamElements` accept `when` and `bind` on an element and `setLocal`, compound `local` writes and `fromLocal` on its events, checked by the same rules as a TSX widget's (spec §8), with pointers into the JSON. The `local` schema is the caller's: `ephemeralManifest({ catalogId, actions, state?, local?, initialLocal? })` takes it with its starting values (both or neither, and `initialLocal` must fit, or it throws `TypeError`). A document cannot declare it: `local`, `initialLocal`, `state` or `manifest` on an element is `invalid-prop` "no such element field". Without `local`, an expression reads only `self` and `shown`. A streamed shell carries its own `when` and `bind`. `Elements<C>` gains `when`, `bind` (bindable props only, never `refProps`) and `TreeIntent` events. `generateElementsSchema(catalog, { local })`, `liveframe gen --elements-schema --local <file>` and MCP `generated_types({ module: "elementsSchema", local })` describe the tree expression grammar and the local intents over the declared keys; without `local` the schema is unchanged. A 0.3.x `renderElements` rejects `when` and `bind` fail-closed ([guide](docs/sdk.md#live-filters-in-agent-json)).
- **A catalog digest for agents (`liveframe gen --digest`, `generateDigest`):** one deterministic Markdown file that tells an agent not on MCP how to write element JSON for a catalog: the element envelope and intents with an example built from the catalog's own kinds, style values, and each kind's description, props with bounds, variants, axes, events and their carries, child rules and style props. With `--capabilities` (`capabilities`) it lists the actions and sources; with `--local` (`local`) the expression grammar and the local keys. It holds no file paths, theme or design-system values, recipes or capability `meta`. `--budget <chars>` (`budget`) fails with `limit-exceeded` at `/digest`, exit 1, instead of cutting the text; `--check` catches drift. MCP `generated_types({ module: "digest", local? })` returns it from the server's catalog and capabilities. The starter ships its own as `@arnilo/liveframe-starter/catalog.digest.md`. Spec §14's agent-tooling line now names the digest ([guide](docs/sdk.md#describe-the-catalog-to-an-agent)).
- **The starter gains five content kinds (`richText`, `chart`, `table`, `tableRow`, `tableCell`):** `richText` draws a closed formatted-text subset (paragraphs, `#`–`###` headings from `headingLevel`, one level of lists, strong, emphasis, inline code, links and backslash escapes) as React elements, never HTML, in one linear pass; a link whose target fails the starter `link.href` rule is drawn as text. `chart` draws a bar or line chart of up to 4 series of 100 values as SVG with a zero baseline, named by `label` and described by `summary` plus a list of every value; each series paints `currentColor` under its `series1`…`series4` slot, so its colour is recipe data and a theme switch recolours it. `table` holds `tableRow` children of `tableCell` children and draws native table markup, with `header` cells as `<th scope>`. None raises an event, and none adds a dependency. Adding them is a minor change: the id stays `starter.ui@1`. The starter design-system sheet grows by 10,663 bytes (509 gzipped) and `primitiveCss` by 1,326. **Action needed:** a design system you wrote for `starter.ui@1` must add a rest recipe for each of their slots, and an app with its own implementations must add one per kind ([README](packages/starter/README.md#the-primitives)).
- **`checkUrl(value, rule)` and `UrlRule` from the root:** the `url` keyword's check (spec §5), for a trusted implementation that draws a link from text; the starter's `richText` uses it.
- **The starter gains five form controls (`radioGroup`, `radio`, `slider`, `progress`, `dateField`):** `radioGroup` holds 2–32 `radio` children and raises `onChange` with the chosen value (a stray `radio` throws and draws the node fallback). `slider` raises `onChange` with a number when a drag or key step ends, never while dragging, and a `maximum` at or below `minimum` draws a disabled slider at `minimum`. `progress` raises nothing; with no `value` it is indeterminate and styled by `mixed`. `dateField` takes ISO dates (`YYYY-MM-DD`) and raises a complete date, or the empty string when every segment is cleared; a value naming no day draws an empty field, and one outside `minimum`/`maximum` is `invalid`. All are built on React Aria Components, with recipes for every state they expose, and the slider and progress fill is the only geometry they compute. Adding them is a minor change: the id stays `starter.ui@1`. The starter gains one peer, `@internationalized/date` `^3.12.4` (the range React Aria Components 1.22 installs). The starter design-system sheet grows by 39,870 bytes (1,582 gzipped). **Action needed:** a design system you wrote for `starter.ui@1` must add recipes for the five kinds, and an app with its own implementations must add one per kind, or the registry check fails ([README](packages/starter/README.md#the-primitives)).
- **A plain DOM adapter (`@arnilo/liveframe/dom`):** draws a surface with no framework, over the same surface core as `/react`. `createDomRenderer({ catalog, implementations } | { catalogs })` runs `/react`'s registry check (one shared function, the same `catalog-mismatch` errors, the same `RendererError` class) and returns `{ mount }`. `mount(container, { validator, theme, designSystem, transparency?, onIntent, confirm?, onEvent?, limits?, fallback, invalid?, focusContinuity?, wrapperClass?, portalClass? })` appends a scoped wrapper and portal container and returns `{ update(tree), set(partial), dispose() }`: `update` validates through the core and draws before it returns, an invalid arrival draws only `fallback()`, and a new theme, design system or transparency runs the §6.4 switching sequence. `implement(definition, draw, hooks?)` binds a primitive to `draw(node, element?)`, which creates or updates its element and is called only for nodes whose core context changed; `node.emit` is stable per node id. `place(parent, nodes)` sets a parent's children with the fewest moves, using `moveBefore` where the engine has it. It carries `<Surface>`'s renderer duties from the same code: a `draw` that throws draws `fallback()` at that node only and is retried on the next arrival; focus continuity, the focus mark, `invalid: "keep-last"`, the switching sequence and design-system motion follow spec §11. An element still playing its exit motion is left in place by `place`. Client-only: no SSR. It sets no `innerHTML` and evaluates no string. `/react` is unchanged; its registry check, focus, switching and motion code moved into modules both adapters share ([guide](docs/renderer.md#render-without-a-framework)).
- **A conformance suite for `/dom` (`@arnilo/liveframe/conformance/dom`):** `domRendererBrowserSuite()` runs the renderer cases against an app's `/dom` implementations, and `domConformancePage()` is its app-owned page host. The cases are `/conformance/react`'s, now defined once: `rendererSuite()`'s structural cases run on the page under the same names (`/dom` has no SSR), then `rendererBrowserSuite()`'s cases without hydration, including the law 4 case that fails a renderer forwarding `setLocal`. `/conformance/react`'s case names, order and outcomes are unchanged ([conformance guide](docs/conformance.md#prove-a-dom-registry)).
- **The starter's `scroll` windows long collections:** `scroll` gains optional `itemCount`, `itemStart` (integers, 0 to 1,000,000,000), `itemSize` (a `size.*` name; the starter design system adds `size.row`, 36 px) and `step` (1 to 200, default 20), and an `onRange` event carrying `{ start, end }`, the visible rows. With `itemSize` set, the implementation reserves the undrawn rows' space as block padding computed from the design value, listens to `scroll` passively once per frame, sets `overflow-anchor: none`, and raises `onRange` when the visible rows come within `step` of the drawn slice's edge. A widget keeps the range in state, binds its source to it and draws at most 200 rows: a 50,000-row list stays within the node limit, and a 20-row range change is a 41-op patch, 13% of the tree's bytes, that keeps the shared rows' elements, focus and scroll position. No library change was needed ([guide](docs/sdk.md#lists-longer-than-the-node-limit)). Because `scroll` now has an event, the starter design system gives its viewport a focus overlay. A tree using the new props fails a 0.3.x validator. **Action needed:** a design system you wrote for `starter.ui@1` must declare `size.row` and add a `scroll` focus recipe, or `validateDesignSystem` rejects it ([migration](docs/migration-0.4.md#action-needed-your-own-design-system-for-starterui1)).
- **Design systems give nodes enter, exit and reorder motion (`motion`):** a root slot's rest recipe may set `motion` to `fade`, `move`, `fade-move` or `none` (`"listItem.default.root.rest": { transitionDuration: "motion.short", motion: "fade-move" }`). A later revision's new node fades in from `opacity: 0` (`@starting-style`), a removed node fades out before it goes, and a node whose siblings changed slides from its old box, each over the recipe's own `transitionDuration`, `transitionTiming` and delay. `motion` elsewhere, a value outside the four, or a motion without a duration is `invalid-document` at `/recipes/<key>/motion`. The projection adds rules only for slots that set it, so a design system without motion projects byte-identical CSS. `<Surface>` gains no option: it marks the surface with `data-lf-motion` after the first drawn tree (so the first tree never animates in), keeps an exiting element `inert` and `aria-hidden` until it has faded, and slides moved siblings in the frame after the commit, before paint; it finds elements only by `domId` inside the surface. Reduced motion and the theme/design-system switching sequence play none. Widget code cannot request or time motion (law 3). No View Transition API is used ([styling guide](docs/styling.md#motion-enter-exit-and-reorder), [renderer guide](docs/renderer.md#enter-exit-and-reorder-motion)). The starter design system uses it on `box.plate`.
- **A slow source can answer `pending` (`sourceOutcome(result, { pending: true })`):** the optional second argument adds a closed `pending` variant, `{ status: "pending" }`, to the envelope; without it the schema is unchanged byte for byte. `SourceResult` (`/host`) accepts `{ ok: false, reason: "pending" }`, which `renderPlacement` shows to a source that declares the variant and turns into a failed render at `/data/<alias>` for one that does not. A pending answer carries no text (a `message` is dropped) and one that also carries a `value` counts as `failed`. It raises the new `source-pending` event, not `source-failed`. The render after the value lands has a new `renderKey`, so it is never skipped. `outcomeScenarios` and `renderScenarios({ outcomes: true })` add a `<name>.pending` scenario for such a source. [The host guide](docs/host.md#answer-a-slow-source-with-pending) shows the loop; the demo host's `tasks.digest` source does it end to end.
- **Renderer conformance covers local state and the interaction additions:** `rendererSuite` gains `failed_binding_draws_the_node_fallback` (derived from the app's examples: the node fallback in the failed node's place, the rest of the surface kept, a `binding-failed` event). `rendererBrowserSuite` gains `when_false_node_is_not_drawn`, `set_local_redraws_and_never_reaches_the_host` (law 4's first conformance case: a renderer that sends `setLocal` to the host fails), `local_writes_apply_with_one_complete_host_intent`, `from_local_intent_arrives_complete` and `focus_mark_moves_focus_once`, driven by the new optional `BrowserFixtures` fields `local`, `compound`, `fromLocal` and `focus`; a missing field fails its case and names it. `conformancePage()` records `onEvent` and exposes `events()` ([migration](docs/migration-0.4.md#renderer-conformance-cases-for-local-state-and-the-interaction-additions)).
- **A filtered list can show an empty state without a round trip (`shown`):** tree expressions gain a third root, `shown` (`{ "$path": "shown" }`, `shown()` in the SDK), an integer counting the node's siblings that carry a `when`, are drawn without a fault and do not read `shown` themselves. `<Text when={ex.eq(shown(), 0)} text="No matches" />` beside filtered rows appears when every row is hidden. Readers are evaluated after their siblings and never counted, so an empty row and a count badge can share a parent; the root reads 0. It is readable only in `when` and `bind` (template props, `$if`, `$let` and `$embed` cannot read it), has no properties (`shown.n` is `unknown-name`), and adds no operator. A parent with no reader is built as before ([migration](docs/migration-0.4.md#a-filtered-list-knows-how-many-rows-it-draws-shown)).
- **`Store.putStateIf`, a compare-and-set for state:** `Store` gains an optional `putStateIf(placementId, scope, expected, next): Promise<boolean>` that writes `next` only if the stored state equals `expected` by canonical JSON (`undefined` matches no stored state), atomically within one `(placementId, scope)`. `memoryStore()` and `fileStore()` implement it (`fileStore()` within its one writing process). `handleIntent`'s `setState` uses it when present: on `false` it re-reads, re-applies the one key and re-checks the state schema, at most four attempts, then returns `version-conflict` at `/state` and raises `intent-refused` with the new reason `conflict`. The uncontended path is still one state read and one write; a store without the method writes with `putState` as before. `storeSuite()` gains `store_put_state_if_compares_by_canonical_json` and `store_put_state_if_is_scoped`, which pass a store without the method ([migration](docs/migration-0.4.md#store-compare-and-set-for-state-putstateif)).
- **A tree can mark the node that takes focus (`focus`):** `UiTree` gains an optional `focus` (the id of one node that exists and is always rendered, with no `when` on it or an ancestor: `not-found` or `invalid-prop` at `/focus` otherwise), and `TreePatch` an optional `focus` (a node id sets it, `null` clears it, omitted keeps it; `diffTrees` emits it only on change). Authors set a boolean `focus` on one element in TSX, element JSON or a template; a second mark is `duplicate-key`, a non-boolean, gated or fragment mark `invalid-prop`. `<Surface>` moves focus with `focus({ preventScroll: false })` after the commit that draws a later accepted revision of the same `surfaceId` whose mark changed; the first tree never moves it. The id resolves only inside the surface's wrapper and portal; a node with no focusable element is skipped and reported as `focus-missed` (`no-element` or `not-focusable`). `SurfaceSnapshot` gains `focus`. `liveframe gen` reserves the name and gives generated primitives `focus?: boolean` ([migration](docs/migration-0.4.md#a-tree-marks-the-node-that-takes-focus-focus)).
- **Array event carries (`carries: { array: { items, maxItems } }`):** a definition's event may carry a bounded array of one scalar type — `items` is a `string` (with `maxLength`), `boolean`, `number` or `integer` schema, each optionally nullable, and `maxItems` is 1 to 256; anything else is `invalid-document` at the event's `carries`. `emit` checks the value against the compiled carry and throws on a mismatch. `bind` fills an array action argument and implicit `setState` an array state key when the items fit under the spec §8 scalar fit rule; `bindAll`, implicit `setLocal` and a value-less `local` write are `invalid-prop`. `checkOffered` re-checks the filled array against the carry and the capability or state schema. `classifyCatalogChange` treats any change to an array carry as major. `implement()` types `emit(event, value: readonly Infer<items>[])`.
- **Intent values read from local state (`fromLocal` on `action` and `setState`):** an `action` intent may carry `fromLocal: Record<string, string>` (1 to 16 entries mapping capability argument names to `manifest.local` keys) and a `setState` intent without `value` may carry `fromLocal: string` (e.g. `action("tasks.escalate", { id }, { fromLocal: { reason: "draft" } })` and `state.set("selected", undefined, { fromLocal: "q" })`). `render()`, `validateTemplate()` and arrival check that each local key is declared (`unknown-name`), each argument exists and fits under the spec §8 scalar fit rule (`invalid-prop`), and no argument is filled twice across literal `args`, `bind`, `bindAll` and `fromLocal` (`invalid-prop`). On `emit` (after any compound `local` writes on the same event), `complete()` fills the targets from the surface's current local state and strips `fromLocal`; `checkOffered` rejects a posted `fromLocal` field (`invalid-prop` at `/fromLocal`), locks literal arguments, and re-checks the filled values against the capability `args` or manifest `state` schema. The authoring MCP `set_state` tool applies a `fromLocal` state event with its `value` standing for the local key, since a preview holds no browser local state.
- **Compound local writes on host intents (`local` on `setState` and `action`):** a `setState` or `action` intent may carry `local` (1 to 4 `LocalWrite` entries, `{ key, value?, until?: "revision" }`) so one event can write local state (e.g. `action("tasks.save", { id }, { local: [local.set("saving", true, { until: "revision" })] })`) and raise its host intent together. On `emit`, confirmation runs first (cancelled or dropped confirmations write nothing), all local writes are validated against `manifest.local` before mutating state (schema failures throw and raise nothing), writes apply in order as one local update, and `local` is stripped before `onIntent`; `checkOffered` rejects any posted `local` field (`invalid-prop` at `/local`). Writes with `until: "revision"` revert when the surface next accepts a revision of the same `surfaceId`, unless superseded by a permanent write; rejected or stale arrivals do not undo them.
- **`<Surface invalid="keep-last">` keeps the last accepted tree on screen after a rejected arrival:** with the new opt-in prop (`invalid?: "fallback" | "keep-last"`, default `"fallback"`, unchanged), a rejected tree no longer blanks the surface. The last accepted tree stays mounted, keeping focus, scroll and uncontrolled input, and raises no intent or local write. The wrapper carries `data-lf-stale` and `aria-busy="true"` until the next accepted arrival. `arrival-rejected` is still reported, no node of the rejected tree is drawn, and with no accepted tree the fallback is drawn. `rendererBrowserSuite` gains `keep_last_invalid_arrival_keeps_the_last_tree_marked` ([decision](decision-logs/2026-11-17-1255-keep-last-valid-tree.md), [guide](docs/renderer.md#keep-the-last-tree-on-screen-when-an-arrival-is-rejected)).

Changed:

- **Action needed for custom `starter.ui@1` design systems.** Declare `size.row`, add a `scroll` focus recipe, and cover the slots and focus states of the ten new kinds. See the [migration checklist](docs/migration-0.4.md#action-needed-your-own-design-system-for-starterui1).

- **Element JSON error kinds match tree validation:** `renderElements` and `streamElements` report `unknown-component` at the element for a missing, empty or non-string `kind`, and `invalid-children` at `children` for a non-array value. See the [migration guide](docs/migration-0.4.md#element-json-error-kinds).

Fixed:

- **Element JSON no longer reads `when`, `bind` or `focus` from `props`, `style` or `events`:** a member of that name was taken as the node field. It is now `invalid-prop` at the member (`/props/when`), in element JSON and templates alike.
- **The tree's 10,000-expression-node bound stops the build:** `render()`, `renderElements` and `streamElements` report it once as `limit-exceeded` and build nothing past it, as for the byte budget. Before, `streamElements` could keep drawing trees past the bound, which a surface then rejected.
- **`streamElements` errors point into the element JSON:** when the stream build stopped at a node, depth or byte limit, or found a broken reference when the document ended, `streamElements` reported the error at the node's key-path id (`/root/button`) instead of its JSON pointer (`/children/0`), unlike `renderElements`. It now gives the pointer `renderElements` gives, as its documentation says. Kinds and messages are unchanged.
- **`renderPlacement` never moves a revision backwards:** when `previous` is passed alongside a `revision` floor at or below `previous.revision` and inputs change, `renderPlacement` now issues `max(revision ?? 0, previous.revision + 1)` and diffs against `previous` instead of emitting a tree with the lower revision and no patch.
- **Fixed (docs) — host guide never resends an applied patch after a skipped render:** [the host guide](docs/host.md) now guards its render, intent-publish and coordination examples with an identity check against the previously served frame so an already-applied `patch` is never resent on a skipped render, and [spec §7.7](docs/spec.md#77-the-host-pipeline) R6 documents the contract.
- **`handleIntent` returns `actions` when the follow-up render fails:** when a dispatched action's outcome or a recorded refusal triggers a re-render that fails, `handleIntent` now returns `{ ok: false, errors, actions }` (typed via `HandleResult`) so the host can persist `actions` without changing its `served` frame; failures before any status is recorded carry no `actions`.
- **`core.accept` leaves an invalid surface invalid on a stale arrival:** when a lower revision for the current `surfaceId` arrives after an invalid arrival was rejected, `core.accept` now keeps `snapshot().valid` false and returns the rejection's `errors` instead of reviving the last valid tree.
- **Surfaces, `<Preview>` and `renderPlacement` forward validation `limits`, and surfaces fail closed on unreadable validators:** `createSurfaceCore({ limits })`, `<Surface limits={…}>` and `<Preview limits={…}>` now forward `ValidateTreeOptions["limits"]` to `validator.validateTree` on each arrival (read without resetting the core), `renderPlacement` step R9 forwards `runOptions.limits` to host `validateTree`, and a validator whose compiled facts cannot be read by the current library copy now returns `catalog-mismatch` at `/validator` with an `arrival-rejected` event instead of throwing.
- **A validator this copy of the library did not compile gets one error everywhere:** `render()`, `renderElements()`, `renderTemplate()`, `checkOffered()`, `createSurfaceCore()` and `<Surface>` report it with the same message, "Expected a validator compiled by this copy of `compileValidator`" (the facts they need live in one table). Kinds and pointers are unchanged: `invalid-document` thrown as `LiveframeFailure` from the renderers, `invalid-prop` at `/validator` from `checkOffered`, `catalog-mismatch` at `/validator` from the surface core and `<Surface>`. Only the message text changed; a validator from a second copy of the package was never accepted.
- **`workerRunner()` starts its render timeout when the worker is ready:** `workerRunner({ timeoutMs?, maxPackages?, startTimeoutMs? })` now waits for `{ type: "ready" }` from the worker entry before starting `timeoutMs`, so cold-start and post-recycle worker boot no longer count against a render's deadline; a worker that does not start within `startTimeoutMs` (default 5,000 ms) is terminated and fails with `render-failed` ("Worker did not start"), and any `ready` from a replaced worker is ignored.
- **`emit` contains a host `onIntent` that throws synchronously:** on the unconfirmed path, a synchronous throw from `onIntent` is now caught inside `raise` so `emit` returns `undefined` instead of throwing into the primitive's event handler, matching the confirmed path; `carries` and `local` schema mismatches still throw `Invalid event value`.
- **`<Surface>` stays on the committed tree when a transition is interrupted:** `<Surface>` accepted each `tree` while rendering, so a `tree` passed inside `startTransition` and then interrupted by an urgent update moved the core ahead of the screen: the urgent render drew the uncommitted revision (or, for another `surfaceId`, reset local state), and `emit` reported it. `<Surface>` now validates and builds the arrival while rendering and applies it when React commits that render, so an interrupted transition leaves the drawn tree, local state and the intent origin on the committed tree. `core.accept` is unchanged; spec §11 now says a framework may call it while rendering only if every render it starts is committed.

Performance:

- **A client mount draws each implementation once:** on a mount that is not hydrating (`createRoot`), `<Surface>` now commits its wrapper and portal container first and draws the tree in the same task, before paint, with `portal` already set, so each implementation renders once instead of twice and never sees `portal` undefined. Hydration is unchanged: the first client render still matches the server with `portal` undefined and draws again after mount.
- **Focus continuity stays inside the surface and no longer reads the host page:** when an update removes the focused element, `<Surface focusContinuity>` now takes candidates from the wrapper and portal container only, so focus can no longer move to a host element after (or before) the surface, matching spec §11's "keeps keyboard focus inside the surface" ([decision](decision-logs/2026-11-17-0149-focus-continuity-candidates.md)). The pre-update snapshot is one scoped `querySelectorAll` with no `getComputedStyle` or `getClientRects`; tabbability is checked after the update, on the candidates tried, only when focus was lost. Focus that a host places on its own element outside the surface during the commit is no longer taken back.
- **`verifiedPackages()` cache hits compare instead of re-hashing:** `verifyStoredPackage` now looks up cached packages by `(id, version)` and installation key (memoised after the first call when `catalog` and `capabilities` are deeply frozen; canonicalised per call otherwise) and confirms a hit with `sameJson` instead of running `validateWidgetPackageShape` and `packageHash`, returning the cached deeply frozen object so reference runners skip re-hashing it too; any difference at any depth misses and takes full `verifyPackage` verification. On the 200 KiB `agent-home` code package, a cached `loadPlacement` with deeply frozen install documents drops from 12.1 ms uncached (15.8 ms prior cached baseline under load) to 1.3 ms CPU (`fileStore`: 11.1 ms uncached / 17.5 ms prior baseline to 0.81 ms), and on the 8 KB template package from 0.79 ms to 0.033 ms.
- **Single-pass streaming canonical JSON hashing for `renderKey` and `packageHash`:** `digest()` (`src/pack/hash.ts`) now streams RFC 8785 canonical JSON UTF-8 bytes directly into the SHA-256 block buffer without allocating the canonical string or UTF-8 byte copy first; every vector in `conformance/hash/` and non-JSON `TypeError` behaviour is unchanged. Across 9 interleaved runs (`bench/hash.bench.ts`), `packageHash` on the 199 KiB `agent-home` code package drops from 5.51 ms to 2.37 ms CPU (2.68×), and `renderKey` over 109 KiB (1,000 rows) drops from 3.44 ms to 1.12 ms CPU (3.14×).
- **Composed components skip re-walking SDK-owned inputs:** `render()` (`src/sdk/render.ts`) tracks the deeply frozen containers it creates in `checkInputs` (and reuses via `inputCopies`) in a module-private `WeakSet`, so `isJson` returns immediately when a composed component receives them instead of re-walking them at every layer; widget-built wrapper objects and caller-frozen inputs are still walked as before. On a 51-node page fed 1,000 rows through six composed layers (`bench/render.bench.ts`), `render()` drops from 2.48 ms (`18.1×` direct) to 0.076 ms (`1.015×` direct, 18.5× faster).
- **`quickjsRunner({ reuse: "package" })` keeps configuration stable across renders:** `@arnilo/liveframe-runner-quickjs` sends `{ catalog, capabilities }` separately from the per-render request and re-parses it in the sandbox only when its text changes, so `runner-kit`'s identity-keyed validator cache hits on subsequent renders in a kept runtime (`reuse: "none"` is unchanged). Inside QuickJS, `compileValidator` accounted for 87.5% (`smallest`) and 15.0% (`agent-home`) of a `reuse: "package"` render; `smallest` drops to 1.31 ms median in `bench/runner.bench.ts` (budget tightened from 8 ms to 4 ms; `agent-home` tightened from 60 ms to 50 ms).

## 0.3.0 — 2026-11-10

0.3.0 is a minor release that may break 0.2.3 contracts, each with a migration entry: see the [migration guide](docs/migration-0.3.md) (breaks, with before, after and a checklist) and the [adopter notes](docs/adopters-0.3.md) (which request each addition closes, and its limits). It releases three packages in lockstep from one Bun workspace: `@arnilo/liveframe`, `@arnilo/liveframe-runner-quickjs` and `@arnilo/liveframe-starter`. Bun ≥ 1.4.2 is the only supported runtime for backend subpaths; no Node runtime is supported. The [compatibility notes](docs/compatibility.md#030) state the 0.3.x promise.

Added:

- **Isolated runner (`@arnilo/liveframe-runner-quickjs`, new package):** `quickjsRunner({ memoryBytes?, stackBytes?, timeoutMs?, reuse?, maxRuntimes? })` runs widget code in QuickJS (WebAssembly) inside a Bun child process the runner owns and kills. The realm holds only ECMAScript built-ins; time (soft interrupt, then `SIGKILL` for a native call), heap and stack are bounded and report `limit-exceeded`; the host re-validates every tree. It renders every proof scenario to the tree `inProcessRunner()` produces. Measured: agent-home 81.5 ms fresh and 47.2 ms with `reuse: "package"` against 1.7 ms in process, so choose it for authors you do not trust. `liveframe mcp` names it in its startup notice when it is installed. See [choosing a runner](docs/packages.md#choosing-a-runner) and [what the QuickJS runner isolates](docs/security.md#what-the-quickjs-runner-isolates).
- **Runner conformance:** `runnerSuite({ runner, catalog, capabilities, packages, isolation?, accepts?, timeoutMs?, slackMs? })` from `@arnilo/liveframe/conformance` proves a `Runner` against spec §7.5: the same trees as the reference renderer, a refused hash mismatch before any load, a thrown widget, a non-function default, an invalid tree, a timeout followed by a successful render and pinned libraries. With `isolation: true` it adds the host-global, state, infinite-loop, memory, recursion, native-hold and forged-answer cases. `conformance/runner/fixtures.json` holds the suite's documents for a port in another language. The reference runners are not isolation boundaries and must not be given `isolation: true`. See [prove a runner](docs/conformance.md#prove-a-runner).
- **Starter (`@arnilo/liveframe-starter`, new package):** a conforming reference catalog (`starter.ui@1`, 25 generic kinds), React implementations, three themes (light, dark, high contrast), a design system and the primitive CSS, passing the catalog, design-system (with contrast), server-renderer and browser suites in Chromium, Firefox and WebKit. It uses node references, a `tone` axis, an extension property and `url` rules. `react-aria-components` is a required peer.
- **Getting-started guide that CI executes:** [docs/getting-started.md](docs/getting-started.md) goes from an empty directory to a template widget installed into a running server and drawn in a browser, with a preview, a refused forged intent and an action dispatched as the viewer. `bun run guide:test` extracts and runs the guide's blocks against the packed archives of all three packages.

- Package dependencies, format and packing: a code package whose manifest declares `exports` is a **library**, and a widget imports its names as `import { TaskCard } from "liveframe:lib/<id>@<version>"`. `pack(draft, { catalog, capabilities, libraries })` resolves the imports against supplied library packages (`unknown-name` for a name not exported, `not-found` for a library not supplied), does not copy library code, emits one `import * as __lf_lib<N> from "liveframe:lib/…";` line per library after the SDK lines and records `manifest.dependencies` (`{ id, version, hash }` pins, at most 16 direct, 32 in the graph, 4 deep, no cycle). The package hash covers the pins. `verifyPackage(pkg, { …, libraries })` re-checks pins, names and the graph, and without `libraries` checks that the code's library lines are the manifest's pins. `rebindDependencies(pkg, { libraries, version })` returns a new package whose pins moved to new library versions without transpiling again. When a stored state fails the new version's schema, `loadPlacement`, `verifyPlacementInputs` and `renderPlacement` start from `initialState`, overlay each evaluated key and, if the result fits, return it with `migrated` (the original failures) instead of `reset`; `renderPlacement` raises `state-migrated` and `Served` carries `migrated`. - Catalog upgrade report: `checkPackages(packages, { catalog, capabilities, runner? })` from `@arnilo/liveframe/pack` runs `verifyPackage` over each stored package and, when a `runner` is supplied, renders every scenario and validates the tree on the host, returning `{ id, version, hash, ok, errors }` per package (scenario errors are prefixed `/scenarios/<n>`). - Stateless host pipeline (render): `@arnilo/liveframe/host` exports `renderPlacement(args)`, which fixes the order of load, bind, resolve-as-the-viewer, fit, skip, render, host validation and diff, and returns a `Served` the host stores and hands back as `previous`. The host injects `store`, `runner`, `resolve` and `onEvent`; the library keeps no state. A re-render with unchanged inputs is skipped, a runner's tree is validated on the host before it can be served, a failed source becomes the widget's `sourceOutcome` envelope (or fails the render at `/data/<alias>`) without copying the resolver's error text, and frozen `HostEvent`s carry ids and reasons, never values. Pipeline overhead is 0.13–0.16 ms beyond `loadPlacement`, the runner and the resolver. See [spec §7.7](docs/spec.md#77-the-host-pipeline) and [the host guide](docs/host.md).

- Stateless host pipeline (intents): `handleIntent(args)` from `@arnilo/liveframe/host` runs `checkOffered`, then the host's `authorize` (for a `setState` write as for an action), then either persists the `setState` write after re-checking it against the manifest, or calls `dispatch` as the viewer, records the `ActionStatus` (`pending`, `ok`, `failed`, `refused`, at most 64 entries) and re-renders. A stale revision is refused, never rewritten; an offered but invalid action is recorded `refused` under the key the tree offered; a throwing `authorize` refuses and a throwing `dispatch` becomes `failed` with a fixed reason, so host text never reaches the widget. Ten `HostEvent`s now cover both functions. See [spec §7.7](docs/spec.md#77-the-host-pipeline) and [the host guide](docs/host.md#handle-an-intent).

- The surface core: `@arnilo/liveframe/surface` exports `createSurfaceCore({ catalog, validator, onIntent, confirm?, domIdPrefix? })`, the host-API-free half of a renderer. It validates arrivals and applies the revision rules, builds a `NodeContext` for each node (effective props, slot classes, style, events, `emit`), completes and gates intents with single-flight confirmation, keeps the surface's local state, applies `setLocal` without calling `onIntent`, and evaluates `when` and `bind` incrementally, re-validating every bound value before a renderer sees it. `<Surface>` is now a thin adapter over it and its public API is unchanged: it applies `setLocal`, hides nodes whose `when` is false, and draws the node fallback for a failed binding. The validator checks every expression against the manifest and the kind's props, bounds them (16 levels, 64 nodes, 16 `bind` entries, 10,000 expression nodes per tree) and keeps `refProps` targets and child-count bounds intact under `when`. `/sdk` exports `local`, `self` and `ex` and accepts `when` and `bind` attributes; templates pass them through and embed values with `$embed`; `liveframe gen` types them; `LocalIntent` and `TreeIntent` join the root types and `diffTrees`/`applyPatch` carry the new fields. Catalog `refProps` declare same-tree relations; rendering resolves them to string ids and validation rejects missing targets with `not-found`. See [the SDK guide](docs/sdk.md#node-references).

Kinds with axes get axis-suffixed slot classes (`lf_<kind>_<variant>__<value>_<slot>`, `slotClass(kind, variant, slot, axes?)`); kinds without axes keep their classes and CSS bytes. See [app states](docs/styling.md#app-states) and [migration](docs/migration-0.3.md#app-declared-states-and-semantics-values).

- URL strings: a `string` schema accepts `url: { schemes, relative? }`, a scheme allowlist checked by one linear function (no `URL` global) in catalogs, capabilities and widget schemas. It rejects control characters and spaces anywhere, compares the scheme case-insensitively, and never accepts `//host` or backslash-led values; failure is `invalid-prop`. `liveframe gen` documents the schemes and the element and published schemas carry an equivalent `pattern`. See [formats](docs/formats.md#the-schema-language) and [migration](docs/migration-0.3.md#url-strings). `catalogSuite` adds `url_props_declare_a_url_rule` for URL-named props that declare no `url` rule, `pattern` or `enum`.

- Template widgets (format and validation): `liveframe-template/1` is element JSON plus a bounded, JSON-structured expression language (38 operators, no strings to parse, no globals, counted work). `@arnilo/liveframe/template` exports `validateTemplate(doc, { catalog, capabilities, manifest })`, `checkExpression`, `evaluate` and the `Template` types; `schemas/template.json` publishes the transport schema. Install checks every path, binding, intent, directive and component use against the manifest and reports `unknown-name`, `invalid-prop`, `invalid-children`, `missing-key` and the rest at pointers into the template. See [formats](docs/formats.md#template-widgets), [spec §7.6](docs/spec.md#76-template-widgets) and [migration](docs/migration-0.3.md#template-widgets).
- Template packages: `pack({ template, manifest, scenarios }, install)` returns a `liveframe-package/1` package whose `template` field replaces `code`; a package holds exactly one of the two, and a 0.2.x verifier rejects a template package fail-closed. The hash covers whichever is present (a code package's hash is unchanged), `verifyPackage()` re-validates the template, and stores, `loadPlacement()` and `renderKey()` need no change. `templateRunner()` (`/preview`) renders template packages without loading any code and refuses code packages; `inProcessRunner()`, `workerRunner()` and `renderTemplatePackage()` (`/runner-kit`) render them too, with identical trees. `RunnerOptions.limits` accepts `steps`. `conformance/hash/template-packages.json` and `conformance/corpus/package/template-*.json` are new. See [packages](docs/packages.md#template-packages), [spec §7.3](docs/spec.md#73-packages) and [migration](docs/migration-0.3.md#template-packages).

A template port of each proof widget renders a tree equal to the TSX widget's over every proof scenario at 2 µs per output node. See [spec §7.6](docs/spec.md#76-template-widgets).

- Template widgets in preview and authoring: `createPreview().update`, `createAuthoring().packDraft` and the MCP `pack_draft` accept `{ template, manifest, scenarios }`, and `pack_draft({ dir })` reads a directory holding `template.json`. `generateTemplateSchema(catalog, { manifest?, capabilities?, structuredSubset? })` in `/sdk/gen`, `liveframe gen --template-schema [--manifest <file>] [--capabilities <file>] [--structured-subset]` and `generated_types({ module: "templateSchema", manifest? })` emit a per-catalog JSON Schema (`urn:liveframe:template-schema:1`) an LLM can target. The outsider guide is [docs/templates.md](docs/templates.md); the demo host installs a template widget that reads a source and pages through `state`.

- Streamed element JSON: `streamElements({ validator, surfaceId, revision?, limits?, maxErrors? })` in `/sdk` returns `{ push(chunk), end() }`. It reads element JSON incrementally (linear in the text, bounded by `limits.bytes`) and returns a valid tree of the nodes completed so far after each chunk that changed them; `end()` returns what `renderElements` returns for the whole text, and successive trees are valid `diffTrees` inputs. Malformed JSON is `invalid-document` at `/$stream/<offset>`. See [the SDK guide](docs/sdk.md#draw-agent-json-while-it-streams) and [spec §7.2](docs/spec.md#72-the-sdk).

- Action results: the host reports each action's status to a widget as the optional input `actions: Record<string, ActionStatus>` (`pending`, `ok`, `failed` or `refused`, with `reason`, `at`, `action` and an `ok` `value`), keyed by action name or by an intent's `resultKey` (`action(name, args, { resultKey })`). A capability may declare `result`, the shape of an `ok` value; `actions` is validated before the widget runs (`invalid-prop` at `/actions/<key>`) and an absent input is `{}`. `render()`, the runners, template widgets (root `actions`), scenarios, preview sessions and `render_scenarios` carry it, and `renderKey` hashes it, so every key differs from 0.2 (`conformance/hash/render-keys.json`). `WidgetProps` gains a required `actions` and `WidgetInputs` is its input form with `actions` optional. - Packages and outcome scenarios are deeply frozen owned copies; rendering gives widgets frozen copies while preserving caller ownership. See [migration](docs/migration-0.3.md).
- **Specification layout:** the same numbered sections now open with rules, followed by contract details and rationale. Historical comparisons and proof results moved to `docs/compatibility.md`; the normative contracts and four laws are unchanged.

- **Bun is the only supported runtime.** Backend subpaths and both new packages declare `engines.bun >= 1.4.2`; the host-API-free subpaths keep the globals listed in the README. The decision is recorded in the [scope decision](https://github.com/ashiqrniloy/liveframe/blob/main/decision-logs/2026-11-05-0238-release-0-3-0-scope.md) and [compatibility](docs/compatibility.md#release-process).

Removed:

- No export, subpath or format is removed. Two inputs that 0.2.3 accepted are now rejected, and both are listed under Changed: fractions on dimension props, and plain objects from another realm.

Security:

- **One realm rule:** every public document validator rejects a foreign-realm plain object with `invalid-document`, so a crafted cross-realm prototype cannot reach a validator by shape (Clay's CL-17).
- **Frozen packages and caller-owned inputs:** a verified package cannot be changed under its hash, and a widget cannot mutate host-owned inputs.
- **Template widgets run no author code,** so `templateRunner()` is a sound production runner for untrusted authors who need only templates; work is counted against `limits.steps`.

## 0.2.3 — 2026-11-04

A host upgrading from 0.2.2 needs no API or data migration; the API register is empty. See the [compatibility notes](docs/compatibility.md#023) for invalid-input outcomes and the [adopter notes](docs/adopters-0.2.md#023--review-fixes-and-simplification) for remaining limits.

Fixed:

- **Custom runner trees are validated on the host:** `createPreview()` and `createAuthoring()` now pass every tree a custom `Runner` returns through the draft's compiled validator before storing or reporting it. A runner that returned an invalid or cyclic tree used to be reported as `ok: true` by `session.render()`, `renderOutcomes` and the `render_scenarios` tool, and a cyclic tree could overflow the stack. They now report the validator's typed errors. Trees from `inProcessRunner()` and `workerRunner()` are unchanged. Only trees that already violated the spec change outcome.
- **Top-level `await using` is rejected:** `checkModule`, and so `pack()`, `bundle()` and `verifyPackage()`, now fail `await using` outside a function (also in a top-level block or `for (await using …)`) with the existing `invalid-document` error. A never-settling `Symbol.asyncDispose` could suspend a module like top-level `await`. `await using` inside an `async` function and synchronous `using` are accepted as before.
- **Failed module links no longer take a cache slot:** `loadModule` no longer caches a package whose SDK header cannot be linked, so such packages no longer count toward the `maxModules` bound.
- **A reassigned package field is no longer trusted as verified:** the reference runners remembered a verified package by object, so replacing `code` (or `hash`, `format`, `manifest`, `scenarios`) after verification loaded the new code under the old verified hash. They now remember the references they verified and hash again when any of them changed. Mutating inside `manifest` or `scenarios` is still not detected; freezing is planned for 0.3.0.
- **Worker error results are shape-checked:** `workerRunner()` re-validated every successful tree but passed a failed result through as sent. A result that is not `{ ok, value }` or `{ ok: false, errors }`, or whose `errors` list is empty, longer than 21 entries or holds a record with a non-string `kind`/`pointer`/`message`/`expected`/`nodeId` or any other field, now becomes one `render-failed` error ("Worker returned a malformed result") and the worker is recycled.
- **`fileStore().listPlacements()` fails closed on a corrupt record:** a placement file that holds `null`, an array, a scalar or an object without a string `id` made the listing return it, or throw a `TypeError` while sorting. It now throws the `invalid-document` `LiveframeFailure` that `read` already throws for invalid JSON, naming the file.

Added (tooling, not published):

- **Dependency audit and SBOM in CI:** CI and the publish job run `bun audit --prod --audit-level=high` and upload a CycloneDX 1.6 SBOM of the runtime closure (`scripts/release/sbom.ts`). A real publish now runs only from a `v*` tag, in the protected `release` environment. No published file changes.

Changed:

- **MCP draft-directory messages name only relative paths:** `pack_draft({ dir })` now reports `draft file "widget.tsx" in "a" not found`, `draft directory "a" not found`, or `… could not be read (EACCES)`, instead of an operating-system error containing an absolute host path. The `kind` and `pointer` are unchanged. `docs/mcp.md` states the `draftRoot` trust model.
- **`sucrase` is bundled into `dist/pack/`, so a consumer no longer installs its dependencies:** `@arnilo/liveframe` now depends only on `acorn`. `commander`, `mz`, `thenify`, `pirates`, `tinyglobby` and the other packages sucrase pulled in with caret ranges no longer reach `node_modules` through Liveframe. `pack()` output is byte-identical; `dist/pack/THIRD-PARTY-LICENSES` carries the licence text of every bundled package. A project that imported `sucrase` only because Liveframe installed it must now depend on it directly.
- **Simpler internals with the same public surface:** dead code and private exports removed, shared internal helpers and tree-byte accounting, and measured closure splits. Lint now fails on warnings. A deterministic differential suite checks install checkers against every published format schema; no schema drift was found.

Deprecated:

- **Fractions on dimension style props:** `width="2fr"` (and `height`, `minWidth`, `maxWidth`, `minHeight`, `maxHeight`) projects to `minmax(0, 2fr)`, which browsers ignore, so it has never had an effect. It is still accepted, and validation and CSS bytes are unchanged; 0.3.0 rejects it with `invalid-prop`. Use `grow={2}` with `basis={0}`, or put the fraction in the parent's `columns`/`rows`. See [`docs/compatibility.md`](docs/compatibility.md#deferred-in-023-delivered-in-030).

Added:

- **Store conformance case:** `storeSuite()` gains `store_lists_only_placement_records`, which fails a store whose `listPlacements()` returns anything but records with a string `id`. Existing cases are unchanged.

Performance (outputs, errors, hashes and declarations unchanged; ratios are paired interleaved runs on a loaded host, new/old):

- **`<Surface>` keeps node reuse with an inline `fallback` or a new `diagnostics` array:** the node cache now resets only when the validator or portal changes or diagnostics are turned on or off. With `fallback={<p>…</p>}` written inline and a parent that re-renders per arrival, unchanged primitives no longer re-render: whole-tree arrival plus React work 121 → 8.4 ms on the 679-node subject. A failed node still shows the current fallback.
- **Whole-tree reuse matches children by `id`:** inserting a row at the head of a list now reuses every existing row, where it used to reuse none. A reorder reuses the children but not their parent.
- **Faster hashing:** `sha256` 1.3–1.5×, `canonicalJson` 0.65–0.68, `packageHash` (512 KiB) 0.70–0.77. Benefits `pack()`, `verifyPackage()`, `loadPlacement()` and `renderKey()`.
- **`diffTrees` reorders in linear time:** 1,000 shuffled rows 0.57; unchanged and single-change diffs unaffected.
- **`bundle()` walks each module once:** 0.79–0.81 on the agent-home widget.
- **`themeCss` reuses a catalog it has already accepted:** a content-checked cache (8 entries) halves repeat calls (0.57); the first call per catalog content costs about 0.19 ms more.

[`docs/adopters-0.2.md`](docs/adopters-0.2.md#022--performance-and-accessibility-additions) maps 0.2.2 capabilities to what shipped. Under the [compatibility policy](docs/compatibility.md#022) (decision [2026-11-01-1747](https://github.com/ashiqrniloy/liveframe/blob/main/decision-logs/2026-11-01-1747-release-0-2-2-scope-and-api-stability.md)), every addition and widening in 0.2.2 is additive under the opt-in and no-break rules.

Performance improvements include whole-tree node reuse in `<Surface>` (memoizing unchanged subtrees between whole trees on arrival) and compiled-validator caching in `compileValidator` (caching immutable catalog and capability closures across calls).

Added:

- **Source binding evaluation:** `bindSources(manifest, capabilities, { params, state, context })` evaluates manifest source bindings at request time without resolving data or granting authority.
- **Render cache key:** `renderKey({ hash, catalogId, params, state, data, context })` in `@arnilo/liveframe/pack` produces a stable SHA-256 hash in canonical JSON over a render's inputs, allowing hosts to skip re-renders and transfers when inputs are unchanged.
- **Recipe contrast audit:** `auditContrast({ theme, designSystem, catalog, registry?, minimums? })` and `ContrastFinding` in the root export resolve every `(kind, variant, slot, state)` recipe pair and measure contrast against WCAG 2.2 thresholds at install time.
- **Accessibility capture axes:** `CaptureMedia` and `CaptureMediaOptions` in `@arnilo/liveframe/preview/capture` define points and options on `textScale`, `forcedColors`, and `reducedMotion` media axes.

Widened:

- **Conformance contrast test:** `designSystemSuite` accepts optional `contrast: true | { minimums }` to fail on audit findings.
- **Focus continuity and async intents in renderer:** `createRenderer` / `SurfaceProps` gains an optional `focusContinuity` boolean to preserve keyboard focus on DOM element disconnection, and `SurfaceProps.onIntent` return type widens from `void` to `unknown` so a host callback may return a promise `emit` hands back.
- **Primitive async emit:** `ImplementationProps` widens `emit` to return `Promise<void> | undefined`: a promise that settles when the host's does when `onIntent` returns one, with the host's value dropped and a rejection contained.
- **Recipe states:** `states` and the recipe key pattern in `schemas/design-system.json` widen to include `current`, `mixed`, `pending`, and `readonly`, positioned in source order between `selected` and `invalid`.
- **Capture media axes:** `CaptureOptions`, `CaptureSession` (`emulate?(media)`), `CaptureCell`, `CapturedCell`, `CaptureInput` and `AuthoringCaptureCell` accept optional media axes and record media coordinates.

Deferred:

- **Node references:** Ratified in [decision 2026-11-02-1219](https://github.com/ashiqrniloy/liveframe/blob/main/decision-logs/2026-11-02-1219-defer-node-references-to-0-3-0.md) and [`plans/evidence/022-node-reference-design.md`](https://github.com/ashiqrniloy/liveframe/blob/main/plans/evidence/022-node-reference-design.md); deferred to 0.3.0 under the no-break rule. Covers `./sdk` `ref`, root `NodeRef`, and `./schemas/*` `catalog.json` (`refProps`).

[`docs/adopters-0.2.md`](docs/adopters-0.2.md#021--clay-review-and-authoring-additions) maps Clay's 0.2.0 review requests (CL-10 to CL-16) and the authoring MCP review to what shipped. Under the [compatibility policy](docs/compatibility.md#021) (R15), every new export, error kind, corpus case, hash vector, optional format (`liveframe/tree-patch/1`), style prop (`deferOffscreen`) and MCP capability in 0.2.1 is additive: existing exports, format meanings, corpus expectations, hash vectors and whole-tree transport are unchanged. One visible MCP error-behaviour fix applies (Task 14.1 M2): a missing inline `pack_draft` key (`files`, `entry`, `manifest` or `scenarios`) now returns `isError: true` with a typed `LiveframeError[]` at that key's pointer instead of the MCP SDK's `Input validation error` string; non-object protocol `arguments` still fail at the protocol layer before the handler.

Added:

- **Validator bundle (CL-10):** `@arnilo/liveframe/validator.bundle.js` is a self-contained, import-free ES module re-exporting the root export (`compileValidator`, `checkOffered`, `capabilitiesFor`, `diffTrees`, `applyPatch`, `validateTreePatch`, every `validate*` format validator and the recipe resolver) with no SDK render path, `renderModule` or `linkPackage`, verified in a bare Node `vm` context with no globals added.
- **Package hash exports and vectors (CL-11):** `@arnilo/liveframe/pack` exports `canonicalJson` and `packageHash`, and `conformance/hash/packages.json` pins `{ package, hash }` vectors (`sha256-` plus lowercase hex SHA-256 of `canonicalJson({ format, manifest, code, scenarios })`).
- **Data `exports` (CL-13):** `./package.json`, `./conformance/corpus/*`, `./conformance/hash/*` and `./conformance/patch/*` resolve through package `exports` under Bun and Node without overlapping `./conformance` or `./conformance/react`.
- **Tree patches and subtree reuse (CL-15):** optional `liveframe/tree-patch/1` wire format (`@arnilo/liveframe/schemas/tree-patch.json`), `TreePatch`, `PatchOp`, `validateTreePatch`, `diffTrees(prev, next)`, `applyPatch(base, patch)` and the additive `stale-patch` `LiveframeError["kind"]` at the root export; corpus cases under `conformance/corpus/tree-patch/` and diff vectors under `conformance/patch/diff.json`; identity-keyed node context and element reuse in `<Surface>`. On the 679-node LF-17 streaming subject, patches measure 228 B gzip and 2.7 ms arrival validation plus React work (median).
- **Deferred offscreen style prop (CL-16):** the `deferOffscreen` style prop takes a `space.*` or `size.*` placeholder height (with responsive values). It projects to `content-visibility: auto` and `contain-intrinsic-block-size`, so a design-system switch on a long surface restyles and lays out only what is on screen. Existing trees are unchanged. A tree that uses it needs a 0.2.1 validator, because 0.2.0 rejects the unknown style prop.
- **Authoring MCP server and `/authoring`:**
  - `set_state({ origin: { nodeId, event }, value? })` and `/authoring` `setState()` apply an offered `setState` event through `session.intent` and return the re-rendered tree under the 256 KiB bound while refusing `action` events (law 4); `PreviewSession.render({ preserveState?: boolean })` lets bound preview pages and capture retain that state for the selected scenario.
  - `generated_types({ module? })` and `/authoring` `generatedTypes({ module? })` return `"types"` (default), `"implementations"` (`--implementations`) or `"elementsSchema"` (`--elements-schema`), byte-identical to `liveframe gen`.
  - `AuthoringConfig.draftRoot` opts the CLI's `pack_draft` into reading `{ dir, entry? }` draft directories with canonical real-path containment and 128-file / 1 MiB read bounds; `/authoring` stays inline-only and host-API-free.
  - Every MCP tool advertises a `title` and explicit `readOnlyHint`, `destructiveHint`, `idempotentHint` and `openWorldHint` annotations.
  - Every MCP tool declares a self-contained `outputSchema` and returns `structuredContent` on success alongside byte-identical 0.2.0 text blocks (using SDK 2.4.0's `{ result }` envelope for non-object roots on `2025-11-25` clients).
  - `AuthoringConfig.maxCaptureCells` and `createAuthoring({ maxCaptureCells })` configure the per-call capture cell bound from 1 to 48 (default 12).
  - `capture_preview({ layout: true })`, `/authoring` `capturePreview({ layout: true })`, `capture(url, { layout: true })` and `liveframe preview capture --layout` report each captured cell's structural `CellLayout` (`width`, `height`, `overflowX`, `overflowing` and per-node CSS-pixel boxes), and the proof agent loop checks layout structurally instead of by pixel height.

Fixed:

- **JSON-only intent cloning and runtime matrix (CL-10):** `complete()` copies and freezes intents in one JSON-only walk without `structuredClone`, `/authoring` counts UTF-8 bytes without `TextEncoder`, and the spec §13 and README runtime matrix lists the exact non-ECMAScript globals each host-API-free subpath needs, enforced by CI across source, `dist/` and bundles.
- **Foreign-realm error message (CL-12):** `validateJson` and `renderModule` detect when a rejected input object has another realm's plain `Object.prototype` and report that the JSON must be parsed inside the sandbox; `docs/packages.md` documents the realm requirement.
- **Package corpus integrity (CL-11):** `conformance/corpus/package/docs/valid.json` carries its real hash and package corpus cases run through `verifyPackage`, with failing `hash-mismatch` and `forbidden-import` cases.
- **Release dist-tags (CL-14):** `.github/workflows/publish.yml` and the `docs/compatibility.md` release checklist move `next` to the released version on non-prerelease publishes so `next` stays at or above `latest`.
- **Switching budget (CL-16):** answers 0.2.0's "Headless WebKit switching exceeds the 16.67 ms budget". The 16.67 ms budget is unchanged, and it now names its span: from the switching attribute change through style and layout of the switch frame (spec §6.4). The WebKit-only 25.1 ms test ceiling is gone, and every engine asserts 16.67 ms. Two changes made this hold in WebKit: the switching fixtures now load the app primitive CSS a host ships, and the agent-home queue rows defer offscreen rendering. On a quiet Linux machine, WebKit's slowest warm switch measured 9–11 ms on the CSS fixture and 13–14 ms through `<Surface>`. Under heavy concurrent load the WebKit tail still exceeds the budget.
- **Unadvertised `outcomes` argument (M1):** `render_scenarios` advertises its boolean `outcomes` argument in `tools/list`, matching `/authoring` and spec §13.
- **Missing-key error shape on `pack_draft` (M2):** removing top-level `required` from `pack_draft`'s input schema routes missing inline keys to handler validation so they return `LiveframeError[]` at `/files`, `/entry`, `/manifest` or `/scenarios` instead of the MCP SDK's validation string.

## 0.2.0 — 2026-10-30

This section shipped as `0.2.0-rc.4` first. `0.2.0-rc.1` and `0.2.0-rc.2` were tagged but never published: CI's `demo:test` ran on Bun 1.4.2, where `bun add --no-save` kept the registry `0.1.0` instead of the packed archive, and `scripts/demo-test.ts` now points the demo's dependency at the archive for the run. `0.2.0-rc.3` published without the four security reminders in the migration guide; `0.2.0-rc.4` adds them. No change to the package between any of the rounds.

[`docs/migration-0.2.md`](docs/migration-0.2.md) covers the three breaking changes; [`docs/adopters-0.2.md`](docs/adopters-0.2.md) maps every adopter request to what shipped.

Changed (breaking):

- **Breaking (0.2.0):** `<Preview>` requires `resultScenario`, the scenario its `result` was rendered for; it no longer infers the label from arrival order or the URL. New optional `selection` makes it controlled (`location` is neither read nor written) and `urlKey` prefixes the uncontrolled URL keys, so two previews can share a page. `data-lf-preview` publishes `urlKey` or `controlled: true`, and capture addresses a keyed page through `<urlKey>.scenario` (CL-01; see `docs/preview.md` for migration).
- **Breaking (0.2.0):** state storage now requires `(placementId, scope)`; pass `""` for shared state. Both reference stores isolate scopes and reject invalid scope strings. Placement deletion removes every scope. Existing 0.1.0 shared state files load without migration (LF-06).

Added:

- **Schema language (LF-04):** `minLength` and `minItems`, `nullable` on any form, and discriminated unions `{ discriminator, mapping }`, with `Infer` and `liveframe gen` producing nullable and tagged-union types. Both the compiled validator and the published JSON Schemas understand them; `pattern` stays rejected in widget-authored schemas.

- **Events (LF-05, CL-08):** `carries` gains `"number"`, `"integer"` and `{ object: <closed schema> }`; `bindAll` merges a carried object into the action's arguments, and `setState` writes it to an object-typed key. `emit` rejects `NaN`, infinities and a non-integer; the validator compares the event type with the target schema and points at the mismatch.

- **Semantics (LF-09):** `form`, `group`, `figure`, `status` and `alert` join the library-fixed list, so a widget can declare a form landmark, a labelled group, a figure or a live region that survives re-renders.

- **Manifests and capabilities (LF-07, LF-08):** an optional manifest `description` and closed `meta` (hashed, carried, never interpreted), capability `meta` per action and source, and `irreversible` beside `confirm`. `list_capabilities` shows the description; `meta` stays host-only unless the authoring config opts in.

- **Renderer (LF-01, LF-08, CL-02, CL-09):** `onIntent(intent, origin)` with `IntentOrigin`, and `checkOffered(tree, origin, intent, validator)` at the root export; an `events` map in the `implement()` context carrying `{ type, confirm, irreversible }`; `<Surface confirm={(intent, meta) => Promise<boolean>}>`; host `wrapperProps` and `portalProps`; and `transparency="reduced"`, which applies the reduced-transparency overrides per surface and suppresses the switch transition.

- **Styling (CL-04, LF-10, LF-11, CL-07):** the reserved `"none"` value on `backgroundColor`, `borderColor` and `outlineColor`; `{ role, alpha }` colour values with a declared `opacity` name or 0–1; vocabulary `contrast` pairs with `minimum`, `maximum` and `lessThan`, enforced by `validateTheme` as `insufficient-contrast`; `placeholderColor` and `scrollbarThumbColor`/`scrollbarTrackColor` recipe properties; and `minHeight`/`maxHeight` style props.

- **Validation and sources (LF-12, LF-14):** `capabilitiesFor(capabilities, manifest)` prunes a capabilities document to what one manifest names, with identical `compileValidator` results; `sourceOutcome(result)` builds the documented per-source outcome envelope, and preview and authoring render its named scenarios.

- **Agent surfaces (LF-16):** `/sdk` exports `renderElements()` and `ephemeralManifest()`, rendering element JSON into the same key-path trees as `render()` with errors pointing into the JSON; `generateElementsSchema()` emits the catalog's element JSON Schema from `/sdk/gen`, with a drift check.

- `inProcessRunner({ maxModules? })` reports its loaded-module count through `stats()` and refuses a new package past `maxModules` (default 256) with `limit-exceeded`; packages already loaded still render. The count is process-wide.

- `@arnilo/liveframe/runner-kit` exports `renderModule()` and a pure `linkPackage(code, resolve)` with a documented linker contract, the in-sandbox half of a host's own runner. `inProcessRunner()` and `workerRunner()` are rebuilt on it with unchanged results (LF-13).

- `@arnilo/liveframe/runner-kit.bundle.js` is a self-contained ES module of the SDK, validator and runner kit for sandboxes with no module resolution. The archive gate checks that it imports nothing, and a CI test renders a packed widget with it under Node's `vm` (LF-13).

- `@arnilo/liveframe/authoring` exports `createAuthoring()` with the seven typed authoring operations, an explicit host runner, injected capture and opt-in outcome checks. `liveframe mcp` adapts these operations without changing its tools (LF-15).

- `@arnilo/liveframe/preview/capture` exports host-independent `capture()` and pluggable `CaptureBackend`, with an explicit `playwrightBackend(playwright)` adapter. Results contain an in-memory file map; snapshots may be absent. CLI output is preserved, and MCP accepts `AuthoringConfig.capture` (CL-05, LF-02).

- `@arnilo/liveframe/sdk/gen` exposes `generate()`, `generateDefinitions()` and `generateElementsSchema()`, byte-identical to the CLI's output, for host build services (LF-02).

- `conformance/corpus/` ships 45 language-neutral cases across all ten formats and `conformance/hash/` ships 45 canonical-hash vectors, both executed by the library's own suite, so a port can prove it agrees on `(kind, pointer)` and on RFC 8785 bytes (CL-06).

- `loadPlacement` accepts optional `{ scope, state }`; explicit state bypasses the state read and follows the same reported-reset rules. `/store` exports `verifyPlacementInputs` for hosts keeping state elsewhere. Store conformance covers scope isolation, bounds and deletion.

Fixed:

- Strip development-only source export conditions from the published manifest and reject missing export targets in the archive gate (CL-03).
- Shipped docs no longer call shipped exports planned, and a CI test keeps it that way (LF-03).

Known limitations:

- **The reference runners are still not sandboxes.** `inProcessRunner()` runs code in the host's realm, and `workerRunner()` bounds time and crashes without restricting what code can reach. `/runner-kit` is the in-sandbox half of a runner, not an isolation boundary. Hostile code needs the app's own isolated `Runner`. See [`docs/security.md`](docs/security.md).
- **`liveframe mcp` still runs agent drafts with the process's permissions** unless the config names an isolated runner. The import ban is syntactic only.
- **Every backend subpath needs Bun ≥ 1.4.2.** `/store/fs`, `/preview/worker`, the in-process loader and the CLI have no Node implementation; the host-API-free and browser subpaths do run elsewhere. `/runner-kit.bundle.js` is the exception among runner artifacts: it runs on a plain ES2022 isolate, verified under Node's `vm`.
- **Capture ships one backend.** `playwrightBackend()` drives headless Chromium; another engine needs the app's own `CaptureBackend`, and a screenshot is only as faithful as that engine.
- **No native Windows forced-colours and assistive-technology audit.** G29's checklist is written (`plans/evidence/020-g29-audit.md`), and the owner waived the run for this release. The conformance kit covers the renderer's semantics, not that audit.
- **Headless WebKit switching exceeds the 16.67 ms budget.** The recorded Linux run measured 18–22 ms; WebKit tests permit 25.1 ms. The owner deferred this issue for 0.2.0; the normative budget remains 16.67 ms.
- **The contrast check is install-time WCAG 2.x.** It measures relative luminance with alpha composited over the declared base, and does not check APCA or re-measure after a theme is installed.
- **Widget-authored schemas cannot use `pattern`**, by design; use `enum` or an app capability instead. General `oneOf`/`anyOf` stay out of the schema language; pick `nullable` or a discriminated union.
- **URL-valued props are the catalog's problem.** The library passes prop values through and never parses one as a URL; constrain `link.href`, `image.src` and the like with a catalog `pattern` or sanitise them in the implementation that renders them. See [`docs/security.md`](docs/security.md).
- **No authorisation, approval flow, storage backend or layout shell ships.** Those stay the app's.

- **Formats and validation** (`@arnilo/liveframe`): component and catalog definitions, themes, design systems with recipes, capabilities, manifests, the UI tree and scenarios, with a published JSON Schema for each at `/schemas/<format>.json`; `validateCatalog()`, `compileValidator()` and a compiled tree validator.
