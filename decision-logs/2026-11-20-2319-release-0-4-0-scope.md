# Decision: Release 0.4.0 scope

## Decision

1. **The 0.3.1 fold.** Plans 033–036, scoped on 2026-11-15 as a `0.3.1` patch, ship in `0.4.0`. No `0.3.1` is published. `scripts/release/api/register-0.3.1.json` stays as the record of those additive changes, layered under `register-0.4.0.json` as `api-stability.test.ts` already does.
2. **The minor-window items.** These change existing behaviour or public error kinds, so after `0.4.0` they wait for `0.5.0`.
   - **Included in 0.4.0:** element JSON error kinds (backlog "Align element JSON's error kinds with `render()` and the arrival walk", plan 036 F1/F2). They become plan 040 Task 1a, run before the release candidate.
   - **Deferred to 0.5.0:** a thrown or rejected `onIntent` reported through `SurfaceEvent` (033 F6), and no prior `patch`/`reset`/`migrated` on a skipped `renderPlacement` (033 F5).
3. **The quiet-host rule.** The 2026-11-09 definition stands: whole-host CPU below 10%, benchmark included. Plan 040 Task 5 makes up to three attempts with `bun scripts/bench-quiet.ts`. If none is clean, the best attempt is recorded and the open proof goes to the Task 8 readiness review, where the owner decides go or deferral under a new decision log. No budget threshold changes without an owner decision log, and the release notes make no quiet-host performance claim unless a clean run exists.
4. **The A2UI first publish.** The owner claims `@arnilo/liveframe-a2ui` with a `0.0.0-stage` token publish, then configures its trusted publisher (repository `ashiqrniloy/liveframe`, workflow `publish.yml`, environment `release`, allowing `npm publish` and `npm dist-tag`) no more than 2 days before the `v0.4.0-rc.1` tag is pushed. CI then publishes `0.4.0-rc.1` with provenance.

## Context

The 2026-11-15 scope decision (`decision-logs/2026-11-15-1251-review-2026-11-15-scope.md`) split the review work into a `0.3.1` patch (plans 033–036) and a `0.4.0` minor (plans 037–039). The patch was never published. All seven plans are committed together in `36da514`, so the patch cannot be released without first building a branch that removes 037–039.

Three backlog items are tagged as needing a minor release. Plan 036's element JSON error-kind alignment is the only one with a ready parity test (`src/__tests__/tree-rule-parity.test.ts`, `known_differences_strict`, three skipped cases) waiting for the change. The other two (`intent-failed` on `SurfaceEvent`, and the skipped-render shape) are P4.

`@arnilo/liveframe-a2ui` does not exist on the registry (checked 2026-11-20: "Not found"). A trusted publisher can only be configured on an existing package, and a new configuration expires if no publish completes within 2 days (docs.npmjs.com/trusted-publishers, checked 2026-11-20). At `0.3.0-rc.1` the two companions were hand-published by token and shipped without provenance (`decision-logs/2026-11-10-0927-manual-first-publish-of-the-companion-packages.md`).

## Alternatives Considered

1. **Publish `0.3.1` first, then `0.4.0`** — rejected: needs a branch without 037–039, a second full release run, and a second set of registry checks for work that is already together.
2. **Include all three minor-window items** — rejected: the other two are P4, have no ready test, and `intent-failed` is additive, so it can ship in any later minor.
3. **Defer all three** — rejected: the element JSON change is P3, small, and the parity test already waits for it. After 0.4.0 it would wait for 0.5.0 with element JSON also carrying `when`/`bind`/`setLocal`, widening what a later error-kind change breaks.
4. **Quiet-host: block the release until one clean run** — rejected: the outcome depends on other projects on a shared workstation, which cannot be controlled (see the 2026-11-09 decision).
5. **Quiet-host: pre-authorise the release with the proof open** — rejected: it would decide before the attempts. The review decides with the evidence.
6. **A2UI: hand-publish the rc by token** — rejected as the default: it ships an rc with no provenance, which configuring the publisher up front avoids.

## Rationale and Evidence

- Fold: the register layering already exists (`api-stability.test.ts` stacks `register-0.3.1.json` under the 0.4.0 register). The fold needs no API change.
- Element JSON: `renderElements` returns `invalid-prop` for a missing or non-string `kind` and for a non-array `children`, where `render()` and `validateTree` say `unknown-component` and `invalid-children`. Spec §7.2 says `renderElements` uses `render()`'s error kinds. Every implementation still rejects both inputs, so no tree is wrongly accepted.
- Quiet host: `scripts/bench-quiet.ts` already measures whole-host CPU per stage and records only clean stages as `pass`.
- A2UI: claiming `0.0.0-stage` first, as plan 032 did, and configuring the publisher just before the tag, keeps the 2-day expiry window short and gives the rc provenance.
