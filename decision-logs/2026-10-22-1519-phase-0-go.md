# Decision: Phase 0 is go — the primitive set passes its parity re-proof

## Decision

Phase 0 is **go**. The 24-primitive catalog plus recipes and style props expresses Synapta's approved agent-home queue to **0.72% / 0.75% / 0.97%** of pixels at 1440 / 1024 / 390 px, against the ≤ 1% bar, with the ten DOM causes and 32 style values listed in `proof/PARITY.md` approved as intended. Phase 1 may freeze the formats. One budget does not hold and becomes a Phase 1 exit criterion: the renderer must cost **≤ 3 µs per node** (2 ms at the 679-node, 50-row selection tree), because the artifact-faithful tree measures 5.75 ms at the proof's current 8.5 µs per node.

## Context

`decision-logs/2026-10-22-0033-phase-0-conditional-go.md` accepted Plan 001's proof conditionally: the model worked, but the agent-home queue differed from the approved artifact by 36–50% of pixels, and Phase 0 stayed open until a follow-up plan added the generic capabilities Plan 001's gaps described and re-proved parity.

Plan 002 (Tasks 1–8) did that:

- `disclosure`, layout `semantics`/`label`, button `current`/`pressed`, and `box` variants `plate` / `rule` / `callout` with a `rail` slot (`catalog/definitions.ts`, `renderer/`).
- `size.*` and `breakpoint` design values, app-declared value names, responsive style values, `position`/`inset`, `fill`/`radius` on `box`, `textAlign`, button `align`, per-side border widths, and typography `letterSpacing` / `textTransform` / `fontStretch` / `fontSizeAdjust` (`proof/styles/types.ts`, `proof/css/project.ts`).
- The artifact's two font faces snapshotted with licences and SHA-256, served by the host and asserted as loaded.
- The queue recomposed from the artifact's landmarks, and the Certified theme/design system tuned as data until the pixels matched.

The evidence, re-run on 2026-10-22: `0.72%` (1440, 9712/1345728 px), `0.75%` (1024), `0.97%` (390), region sizes equal to the artifact's (1376×978, 960×977–978, 358×1610), no diagnostics, `281` positional DOM differences and `32` style values per width. `proof/scripts/inventory.ts` collapses wrapper elements and shows that the 281 DOM paths come from ten causes, each a markup choice of an existing primitive. The other benches: `runtime.bench` 1.75 ms, `clay.bench` 0.79 / 1.30 ms, host `setState` round trip 7.67 ms against 50, design-system switch 3.80 / 0.80 ms against 16.67 — and the render benches over budget (below).

## Approval

- Proposed by: agent (recommendation) and user (verdict).
- Approved by user: Yes.
- Approval evidence: presented with three options — go with a per-node render budget, conditional go until the render path met 2 ms, or no-go — and the user replied: “go with recommendation”.

## Alternatives Considered

1. **Conditional go (keep Phase 0 open until the render bench meets 2 ms)** — rejected: the cost is in the proof's render/validate path (`assertJson` re-walks the input per render, 16% of samples; validation re-checks every node at 25%), not in the primitive model, and holding the formats closed delays Phase 1 for an implementation cost that Phase 1 replaces anyway. The per-node gate keeps the requirement enforceable.
2. **No-go, revisit §5–§6** — rejected: the parity criterion is met and no UI needed a product-shaped primitive, raw CSS or literal colour, so §12's stated failure condition does not occur.
3. **Go and drop the render budget** — rejected: the 2 ms bench is an owner-set budget in spec §9, and silently raising it would hide a 3–4× regression. The budget changes shape (per node), not direction.

## Rationale and Evidence

- **The parity bar is the look's authority.** Two control experiments bound the metric: the artifact captured against itself with a 0.03 px page offset differs by 0.15%, and a 0.5 px shift by 3.7% — a figure larger than the remaining gap. Aligning the widget's capture region to the artifact's page origin, which `proof/scripts/parity.ts` now does, is therefore required for the number to measure look rather than sub-pixel phase. With alignment and `-webkit-font-smoothing: antialiased`, the residual ink-coverage difference is 0.23%.
- **Every remaining difference has a cause in the primitive model, not a gap.** Ten DOM causes: React Aria tab markup; inline icon glyphs; rules as `separator` elements; `text` spans inside `dt`/`dd`; prose without a paragraph; actions as buttons with intents (law 4); group labels as `text`; button label slots; the options `menu`; marker spans with `role=img`. Thirty-two style values, of which 27 are anchor correspondence after the recomposition, 3 are `tabs`/`grid` choices already recorded in `GAPS.md` for the switch budget, and 2 are `position: relative`, which the closed `position` enum does not carry and which has no visual effect.
- **The UIs still obey the four laws** with the new surfaces: `fill` accepts only declared non-surface roles (`fill_accepts_only_declared_fillable_roles`), responsive values are closed data (`responsive_style_values_are_closed_data`), `semantics` is a closed enum with `terms`/`term`/`detail` child rules (`semantics_are_a_closed_enum_with_terms_child_rules`), and no projection accepts injections or unresolved values (`projection_rejects_injection_missing_recipes_and_unresolved_values`).
- **The over-budget number is a rendering-path cost.** The artifact's row is a grid row (marker, title button, mono word, meta spans), so a 50-row tree is 679 nodes, 13.6 per row. At 8.5 µs per node that is 5.75 ms. Nothing in §5–§6 requires 8.5 µs: the proof's `assertJson` and `validate` were written to be obviously correct, and Phase 1 owns the real renderer and validator.

## Consequences

- Phase 1 freezes the catalog, style-prop and projection formats; a change after this point needs a new decision log.
- Phase 1's renderer and validator carry a hard budget: **≤ 3 µs per node**, measured on the same 50-row benches, and the design-system switch stays ≤ 16.67 ms with a warmed container-query cache.
- G30 (per-row icon hues) and G31 (a tab's count in its own face) move to Phase 2's composition surface; they are inside the pixel budget today, so neither blocks the freeze.
- The parity script is now part of the regression set: a future format change that moves a pixel must re-capture with the artifact page origin aligned, or the number will report antialiasing rather than look.
- Revisit this decision if a fifth UI needs a capability that only a product-shaped primitive or raw styling can express, or if Phase 1 cannot reach 3 µs per node without changing the tree shape the parity bar forced.
