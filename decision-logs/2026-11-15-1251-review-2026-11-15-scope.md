# Decision: 2026-11-15 review release scope and 0.3.0 API baseline

## Decision

Fix the reproduced defects (`D1`–`D7`), wall-clock test gate issue (`G1`), request-time and browser performance findings (`P1`–`P3`, `P5`–`P6`), and structural findings (`A1`–`A6`) in `0.3.x` (`0.3.1`, plans `033`–`036`). Every `0.3.x` change must stay patch-safe under the 0.3.x promise (`docs/compatibility.md`): additive only (`added` or `widened` entries in `scripts/release/api/register-0.3.1.json`), changing an outcome only where today's outcome is a named defect, and changing no corpus expectation, hash vector or published schema meaning. (`P4` stays in `0.3.1` unless its browser measurement/decision changes behaviour, in which case it moves to `0.4.0`; `A4` is opt-in.)

Place `G2`, `G3` and the capability additions `F1`–`F12` in `0.4.0` (plans `037`–`039`). Lift the two spec §14 v1 non-goals for `0.4.0`:
- **F8** ("Renderers other than React"): lift the non-goal so `@arnilo/liveframe/dom` stays in `0.4.0` scope (Plan `038` Tasks 5–6 remain active, with design settled in Plan `038` Task 1).
- **F11** ("A2UI or other wire interop"): lift the non-goal so `@arnilo/liveframe-a2ui` stays in `0.4.0` scope (Plan `039` Task 4 remains active, with design settled in Plan `039` Task 1).

(`docs/spec.md` §14 stays unchanged for `0.3.x` and is updated when those `0.4.0` designs and tasks execute.)

Gate `0.3.x` against `scripts/release/api/0.3.0.json` (generated from the `v0.3.0` tag) through `scripts/release/api/register-0.3.1.json`, starting at `[]` and permitting only `added` and `widened` entries. Keep `scripts/release/api/register-0.3.0.json` as release history. No version bump or npm publication is authorized by this decision.

## Context

A comprehensive package review of `main` at `b4e2359` on 2026-11-15 (`plans/evidence/033-review-findings.md`) reproduced six defects in the host pipeline, surface core and worker runner plus one synchronous-throw inconsistency in `emit` (`D1`–`D7`), identified 23 wall-clock test assertions causing non-deterministic failures in `bun run check` (`G1`), measured request-time and browser bottlenecks (`P1`–`P6`), surfaced structural maintainability risks (`A1`–`A6`), and catalogued capability gaps (`G2`–`G3`, `F1`–`F12`).

In addition, `plans/backlog.md` ("Generate the core 0.3.0 API baseline before 0.3.1") recorded that `scripts/release/api/` held `0.2.3.json`, `register-0.3.0.json` and the two companion `0.3.0` baselines, but no core `0.3.0.json` baseline yet.

## Alternatives Considered

1. **Keep `scripts/release/api/0.2.3.json` plus `register-0.3.0.json` as the checkout baseline** — rejected: an `added` entry only has to be absent from the baseline, so a later edit to a declaration added in `0.3.0` would pass unreviewed (`plans/backlog.md`).
2. **Use an empty register that forbids additions (as `0.2.3` did)** — rejected: `D3` (`HandleResult` / `handleIntent` optional `actions`) and `D5` (`limits` option) require additive declarations permitted by the 0.3.x compatibility promise.
3. **Hold defects and performance fixes until `0.4.0`, or keep the §14 non-goals closed for `F8`/`F11`** — rejected by the owner: defects and additive performance/structural improvements ship promptly in `0.3.x`, while both the DOM adapter and A2UI converter move forward in `0.4.0` under explicit design decisions (`038` T1, `039` T1).

## Rationale and Evidence

- `plans/evidence/033-review-findings.md` documents the reproductions (`D1`–`D7`), request-time measurements, and baseline `bun run check` wall-clock failures at `b4e2359`.
- `docs/compatibility.md` ("The 0.3.x promise") explicitly requires `0.3.y` patches to compare against a baseline generated from `v0.3.0` while keeping `register-0.3.0.json` as history and allowing additive exports and options without breaking existing callers, schemas, corpus expectations or hash vectors.
- `scripts/release/api/0.3.0.json` is generated from a detached temporary `git worktree` at `v0.3.0` (`18f2fe1`) with `bun install --frozen-lockfile` and `bun run build`, matching the `0.2.3.json` procedure.
