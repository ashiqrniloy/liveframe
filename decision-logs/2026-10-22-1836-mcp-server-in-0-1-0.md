# Decision: The authoring MCP server ships in 0.1.0

## Decision

`liveframe mcp`, the authoring-time MCP server for coding agents, ships in the 0.1.0 release instead of after it. Roadmap Phase 8 keeps its number but runs before Phase 6. Its tools now include preview capture, and they render through a preview session. Its scope is unchanged: authoring time only, never installing, placing or approving a widget, and never running an action.

This supersedes only the timing in `decision-logs/2026-10-22-0902-authoring-mcp-server-for-coding-agents.md` ("It follows the 0.1.0 release (Phase 6) and the reference-host phase (Phase 7)"). Everything else in that record stands.

## Context

`decision-logs/2026-10-22-1600-preview-and-runners.md` put the preview, including `liveframe preview capture`, into 0.1.0, and left the MCP server after the release. When asked whether "everything discussed so far" included the MCP server, the owner moved it into 0.1.0 as well.

## Approval

- Proposed by: user
- Approved by user: Yes
- Approval evidence: "Move the MCP server into 0.1.0 too".

## Alternatives Considered

1. **Keep the MCP server after 0.1.0 and let agents use the CLI.** Not chosen by the owner. Coding agents with a shell could capture through the CLI, but agents without a shell, and those that prefer typed tools, would wait for a later release.
2. **Renumber the phases so the MCP server becomes Phase 6.** Not chosen. Accepted decision logs and proof reports name Phases 6, 7 and 8 by number, and those records stay immutable. Renumbering would make them point at the wrong phases.

## Rationale and Evidence

- The server's dependencies are all built before Phase 6: the SDK and runners (Phase 2), the renderer and preview (Phase 4). Nothing in Phase 5 or 6 is a prerequisite.
- The tools wrap capabilities 0.1.0 already ships (definitions, generated types, `pack()`, preview sessions, capture), so the server adds a dependency (the MCP SDK) but no new model.
- Keeping phase numbers stable and stating the order in the roadmap preserves every existing reference.

## References

- `docs/spec.md` §3, §7.5, §13, §14 — updated.

- `decision-logs/2026-10-22-1600-preview-and-runners.md` — preview and capture in 0.1.0.

## Consequences

- 0.1.0's scope now also includes `liveframe mcp`. The MCP SDK is an optional peer dependency used only by that command, justified in its plan.
- Spec §14 no longer lists the MCP server as post-v1.
- Revisit if the release must be cut before the server is ready. The fallback is the CLI capture path, which is already in 0.1.0.
