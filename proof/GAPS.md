# Phase 0 gaps

These are proof findings, not finalized changes to the normative spec. No primitive has been added. Source paths below are relative to `proof/references/`; commits are recorded in `references/SOURCES.md`.

## Task 3 — theme authority and vocabulary

- **Rack typography ownership:** Clay's `packages/design-rack/docs/index.md` §2 and decision `2026-08-28-2234` separate content themes, user typography and design systems. Liveframe spec §6.1 puts typography in the theme. `styles/rack/theme.ts` supplies proof-host typography using the font stacks and base/label/meta sizes in `clay/design-artifacts/approved/rack-kit-and-pages/rack.css:9–17`; heading roles supply a proof scale. This does not migrate or redefine Clay's user preferences. Task 12 must revisit the ownership mismatch.
- **Shared colour roles:** both themes declare the same vocabulary in `styles/types.ts`. Modus Operandi's `designTokens` map directly; `text.primary` and `surface.scrollbar` come from its `textStyles` entries `text` and `scrollbar`. Rack's aliases `surface.base`/`raised`, `accent.fill`/`fill.hover`, `text.on-accent`, `status.critical` and `shadow.highlight` reuse case/module/accent/error colours. The Rack primary hover recipe retains its source opacity of 0.86; the additional `accent.fill.hover` alias does not invent a new palette entry.
- **Roles absent from Certified:** `surface.case/module` alias bg/surface; text meta/disabled and kbd/status reuse its muted/foreground roles; border roles reuse line/line-2/control/focus. Diagnostic ink roles use danger/attention/success/info ink. Certified has no five-patch identity vocabulary: `patch.1–5` reuse danger/info/success/accent/foil colours. It also has no diagnostic fill roles: diagnostic soft roles reuse its neutral hover wash, preserving its no-chromatic-fill direction. These aliases satisfy the structural switch contract but do not prove Rack's identity-versus-status distinction under Certified; Task 10 must inspect this, and Task 12 must report the limitation.
- **Transparency:** Rack's 247 translated source recipes replace `transparent` with `colour.transparent`; both themes own its colour value. Every other source recipe field and all 14 source values are retained. Tests compare with the pinned manifest after that sole normalization, including nested shadow roles.
- **Scope:** only Certified light and Modus Operandi light are supplied. Dark/contrast modes, OS forced colours, font loading and pixel parity are not established by this data task; CSS projection and parity belong to Tasks 5 and 11. Typography sizes and spacing are numeric CSS pixels; rem-based Certified tokens use the reference's default 16px root.

Because Task 2 definitions do not declare per-kind state subsets, the proof materializes all eight spec §6.2 states for every catalog slot. It does not infer behavior or state from a recipe.

Other source variants (`textInput.search/bare/command/inline/secret`, `label.display/section/caption/detail/status/eyebrow/accent`, `panel.fixed/transient/tint`, `flex.column`, etc.) remain in the translated source inventory rather than becoming widget variants. Product-shaped source families (`case`, `module`, `lamp`, `jack`, `pips`, `io`, etc.) are reference styling only: they are not installed as catalog kinds or returned in the active catalog recipes. Tasks 7–9 must compose the corresponding UI from primitives and record any geometry that roles/style props cannot express.

The Rack package docs §5 say 273 keys, but the pinned manifest actually has **247 recipes**. The manifest is the proof authority; tests lock its exact inventory.

## Task 3 — style format and parity handoff

- Rack recipes use undeclared `spacing.none/xxs/xs/sm/md/lg/tooltip` references and `expo-out`. The proof supplies spacing values 0/4/8/12/16/24/6 and the documented `[0.16, 1, 0.3, 1]` easing. Both systems also expose the same `space.0–7` layout token names (0/4/8/12/16/24/32/48). These are explicit proof values; exact context-specific padding still needs Task 11 parity.
- `styles/types.ts` is a closed proof subset, not the published Phase 1 format/schema. It includes Rack's typed outline, opacity, saturation, shadow and press-shift fields. Task 5's projector must handle these fields, axis padding and theme typography, rather than pass through CSS strings. Value references are checked by property domain, including when a colour role and a border-width token both use `border.hairline`.
- Certified recipes translate `.btn`, `.field`, `.menu`, `.tab`, `.check`, `.switch` and `.dialog` from the pinned stylesheet/artifact. Default button maps to outline, ghost to quiet, danger to quiet danger; primary is filled. Box stays unpainted so plates/cards remain composition. Pop/mount shadows split geometry from theme colour roles. The current type subset does not claim exact typography tracking/stretch, control heights, text decoration, multi-state precedence or every context-specific border. Tasks 5/11 must record or resolve parity gaps rather than introduce product-shaped primitives or raw widget CSS.
- Completeness and closed-property/value checks run in `tests/styles.test.ts` for these trusted proof fixtures. A reusable runtime install validator remains Phase 1; this task does not claim to accept untrusted external themes or design systems.

## Task 5 — renderer and projection handoff

- `css/project.ts` projects all 536 recipes in each installed system, including typography, axis padding, opacity, shadows, blur/saturation, transitions, outlines and press-shift transforms. Stable slot classes react to native and React Aria state attributes; root states also reach their internal slots. The proof applies one active projection globally by replacing a stylesheet's text in one operation. Simultaneous independently styled surfaces are outside this proof. Forced-colours behavior is exercised in Chromium; this is not an audit on Windows hardware or with assistive technology.
- Every candidate has a compiled React implementation in `renderer/primitives/index.tsx`. Menu and tab collections use validated child nodes directly because arbitrary React component wrappers are not Aria collection entries. This adds no catalog prop or product-shaped primitive. Native scrollbar colours use theme roles; WebKit thumb rules also project the scrollbar slot. Platform scrollbar geometry remains native.
- The icon implementation uses a small host-owned glyph map and a generic fallback, with decorative glyphs hidden and named icons exposed as images. Tasks 7–9 must supply any missing reference glyphs before Task 11 claims parity. Fonts are named by the existing themes, not downloaded by this task. Exact control geometry, typography tracking/stretch, multi-state precedence and source-specific decoration remain parity findings for Tasks 7–11.
- `textField` edits remain local until blur or Enter; multiline submits on Ctrl/Cmd+Enter and composition Enter does not commit. The catalog's existing `onChange` is the commit event and `onSubmit` is separate. Select, checkbox, switch and tabs retain local changes through unrelated revisions and accept changed host prop values. Dialog dismissal closes locally and emits `onClose`. Task 6 still owns dispatch-time schema checks, authorization, persistence and the actual widget rerun; static action arguments are forwarded unchanged, while absent `setState.value` receives the event payload. This does not finalize the spec's `onCommit` naming or add a dynamic action-argument binding format.
- Chromium browser tests run inside `bun test`; install the browser once with `timeout 600s bunx playwright install chromium`. Playwright was brought forward from Task 11 to prove renderer behavior rather than relying on a simulated DOM. The fixture sends only validated synthetic tree data and compiled host code to the browser, hydrates SSR markup, and fails on browser errors. Pixel parity, four reference widgets and a live host remain Tasks 6–11.
- No normative spec meaning, primitive list, published export or package version changed. Projection guards reject missing recipes/references and unsafe CSS serialization, but the reusable untrusted theme/design-system installation validator remains Phase 1, as recorded above.

## Task 7 — agent-home composition

- **Composition:** `widgets/agent-home/` expresses the category tabs, decision/task/alert focus cards, subject-first rows, folded-alert annotation, stale notice, reference disclosures, widget options, loading/empty/failure/read-only states, task escalation dialog and alert Snooze menu with existing catalog primitives. No primitive, catalog prop, recipe, dependency or raw widget CSS was added. The three opaque fixture cursor chains live in one `cursors` state object. A single Load more intent advances each permitted, non-exhausted chain, even when a category filter is active; rows accumulate through the walked pages and selection is retained by id. An exhausted chain keeps its last cursor. Initial counts are totals (12); Showing counts actual visible loaded rows (6 initially), rather than copying the artifact's static Showing 12 onto six drawn rows.
- **Actions and permissions:** the manifest declares closed argument schemas for decision review, claim, escalation, acknowledge, snooze, conversion and retry. Permissions are synthetic host-supplied params: read-only hides mutation controls and the reason field, no-escalate hides escalation, and no-alerts omits its rows, counts and tab. Dispatch accepts only currently offered intents. This is a proof of composition and intent boundaries, not production authorization. Decision review and retry are logged alongside the other actions, rather than navigating to an unimplemented proposal page or fetching a real backend. Actions deliberately leave the card/dialog unchanged because the proof dispatcher logs without executing operations.
- **Reason commit:** typing stays local; blur or Enter commits the reason into widget state. The widget offers escalation only for a committed 1–500-code-point string, and the action schema independently rejects empty or oversized reasons. The text field's native maxlength counts UTF-16 units, so a browser may admit fewer than 500 non-BMP characters; the wire schema counts Unicode code points. The reason is a placement draft retained across dialog closes; the action always names the currently focused task. No dynamic action-argument binding or multi-intent event was added.
- **DOM and styling parity remains Task 11:** candidates have no semantic article/aside/definition-list wrappers, disclosure primitive, button children or current/pressed accessibility prop. The composition uses generic boxes/stacks, labelled headings, a subject button plus metadata, an explicit Selected word and selected surface, and the existing accessible Reference popover in place of native details. Task and related-proposal facts are text; the alert outcome explanation is in its lead/note rather than the artifact's separate decorated note. The fixed two-column grid has no responsive breakpoint or sticky-focus contract. Source marker SVGs, hairline plate/row rules, state glyph geometry, exact alignment/typography, mobile stacking, and semantic DOM differences are unresolved parity findings. No product-shaped variant or styling escape was introduced to hide these gaps. Task 11 must measure them, and Task 12 must include them in the go/no-go; Task 7's browser tests establish behavior, not pixel or DOM equivalence.
- **Performance:** row components receive only their displayed fields, and use a box, full-width subject button and metadata text. This avoids passing each task's unused focus-card payload through composed-prop validation and avoids an extra row wrapper. `tests/agent-home.bench.ts` measures 1,000 actual queue rerenders with changing selection across 50 tasks after 200 warmups against Task 4's 2 ms mean budget. `tests/agent-home.test.ts` and `tests/agent-home-browser.test.ts` cover selection/filtering, unequal cursor chains, reason bounds, permissions, all card controls, local input/menu behavior, hydration and browser-bundle isolation. Evidence images and pixel/DOM diffs remain Task 11.
