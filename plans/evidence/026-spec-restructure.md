## Audit method and verification

Read the baseline with `git show v0.2.3:docs/spec.md`. Each nonblank source line outside headings/fence delimiters is split at sentence punctuation followed by an uppercase letter or inline code; inline code is protected from splitting. Bold/list markers and whitespace are normalized only for comparison. Code and table lines each form one unit. Thus `L117 S1–S21` identifies the first 21 sentences of that source line in order, including the “The schema language” lead-in.

For every unit, the audit found its complete normalized text in a destination line span, or verified the explicit editorial replacement in that span. Adjacent sentence units from the same source line are grouped only when they map in order to the same nearby destination. “Exact” therefore covers each sentence in the indicated range, including every bound, rejection, error pointer and compatibility guarantee. Histories found in compatibility remain exact quotations of the source text. The 16 editorial replacements retain referents/obligations or move a release clause; they do not settle the ambiguities above.

The one-off audit also compared the complete fenced-block arrays and heading arrays, and counted prose words. The committed regression tests pin the headings and laws, paragraph length, rules-first layout and absence of bare release references. Commands: `timeout 30s bun test src/__tests__/docs-spec-structure.test.ts src/__tests__/docs-links.test.ts src/__tests__/docs-wording.test.ts`; `timeout 900s bun run check`. The existing docs-links test validates file/archive paths; the new heading test supplies the fragment-preservation proof it did not previously cover. No guide test quotes changed spec wording.
